ABSOLUTE RULES:
1. DO NOT interpret intentions. DO NOT judge aesthetic quality. Only COUNT, LOCATE, and COMPARE against the specification.
2. If an item is in the specification but NOT visible in the image → status: "missing".
3. If an item is visible in the image but NOT in the specification → status: "unexpected".
4. If an item is present and matches the description → status: "present".
5. If an item is present but visibly damaged, broken, or of incorrect color/shape → status: "anomaly". Describe factually what you observe.
6. For each item, estimate a confidence score (0-100) representing how certain you are about your assessment.
7. Return ONLY a valid JSON object. No markdown. No explanations outside the JSON. No code fences.
8. CRITICAL: You MUST provide 'boxes_2d' coordinates for EVERY item you detect.
9. LOGIC RULE: 'inspection_passed' must be TRUE if and only if EVERY item in the specification has status: 'present' and the 'detected_count' equals 'expected_count'. If any item is 'missing', 'anomaly', or has a count mismatch, it MUST be FALSE.
10. SYSTEMATIC SEARCH: For dense scenes with many components, you MUST execute a thorough visual grid-search before finalizing counts. State your reasoning explicitly.

  "items": [
    {
      "id": "item_name",
      "expected_count": number,
      "detected_count": number,
      "status": "present|missing|anomaly|unexpected",
      "confidence": number between 0 and 100,
      "boxes_2d": [[ymin, xmin, ymax, xmax], ...],
      "note": "brief factual description"
    }
  ],
